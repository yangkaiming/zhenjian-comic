# 帧间漫画 · 数据连接架构说明

> 本文说明本应用（Electron 桌面端 + 内置 Node 后端 + MongoDB）是如何连接到「线上数据」的。
> 所有结论均来自实际代码，文件路径见各小节标注。

---

## 1. 一句话概览

应用启动时，**Electron 主进程会在本机拉起一个 Node 后端（Express，端口 9527）并同源托管前端**。
前端所有数据请求都打到这个 `http://127.0.0.1:9527`，后端再通过 **Mongoose 连 MongoDB**（测试库 / 线上云库二选一），
并通过**爬虫服务 + 图片代理**对接外部漫画源（MangaDex / 动漫屋 / 包子漫画等）。

```
用户操作
  → React 组件 (web/src)
    → web/src/api.ts  (fetch → API_ORIGIN + /api/...)
      → Electron 注入的 window.comic.serverOrigin  (= http://127.0.0.1:9527)
        → 内置后端 server (Express)
          ├─ Mongoose → MongoDB  (测试库 127.0.0.1:27017 / 线上库 MONGODB_URI_PROD)
          ├─ crawler   → 外部漫画源 (MangaDex / dm5 / baozimh ...)
          └─ /media/img → 远程图片 CDN（防盗链代理，SSRF 白名单）
```

## 2. 前端层：请求发往哪里

文件：`web/src/api.ts`

- 后端地址由 Electron 注入的全局对象决定，兜底默认本机 9527：

```13:16:web/src/api.ts
export const API_ORIGIN: string =
  (typeof window !== 'undefined' && window.comic?.serverOrigin) || 'http://127.0.0.1:9527';
export const bridge: ComicBridge | undefined = typeof window !== 'undefined' ? window.comic : undefined;
```

- 统一请求封装 `request<T>()`：自动带 `Authorization: Bearer <token>`、30s 超时（超时抛「请求超时」避免永久卡 loading）、统一错误解析。
- 业务接口集中在 `api` 对象，例如：
  - 漫画/章节：`comics`、`detail`、`chapters`、`chapter`
  - 用户：`login`、`register`、`me`、`updateProfile`
  - 书架/历史：`shelf`、`addShelf`、`updateShelf`、`history`、`saveHistory`
  - 评论/反馈/举报：`comments`、`addComment`、`createFeedback`、`createReport`
  - 管理后台：`reports`、`feedbackList`、`users`、`adminRecommend`
  - 应用更新：`appLatest`（`GET /api/app/latest`）
- **图片地址**两条规则（`web/src/api.ts`）：
  - `assetUrl()`：已是 `https:`/`comicimg:`/`blob:` 等绝对地址则原样；否则拼 `API_ORIGIN`。
  - `pageImageUrl()`：阅读器页图一律走后端代理 `${API_ORIGIN}/media/img?u=<编码后的远程URL>`（见第 4 节原因）。

## 3. Electron 桥接层：把「后端地址」注入前端

文件：`electron/preload.ts`

通过 `contextBridge` 把 `window.comic` 暴露给渲染进程，`serverOrigin` 取环境变量，兜底 9527：

```28:29:electron/preload.ts
const api: ComicBridge = {
  serverOrigin: process.env.COMIC_SERVER_ORIGIN || 'http://127.0.0.1:9527',
```

该对象还封装了窗口控制、全屏、保存图片、打开外部链接等原生能力（`winMinimize` / `toggleFullScreen` / `saveImage` / `openExternal` 等）。

## 4. 主进程：启动内置后端 + 同源托管前端

文件：`electron/main.ts`

- 端口与后端地址固定本机：

```134:135:electron/main.ts
const PORT = Number(process.env.PORT || 9527);
const SERVER_ORIGIN = `http://127.0.0.1:${PORT}`;
```

- 打包后标记数据环境为 `prod`，并优先加载 `.env.prod` 再补 `.env`：

```13:17:electron/main.ts
if (app.isPackaged && !process.env.COMIC_DATA_ENV) {
  process.env.COMIC_DATA_ENV = 'prod';
}
loadEnvFile(path.join(__dirname, '..', '.env'));
```

- `startBackend()`：**打包版直接 `require(server/dist)` 在主进程内启动后端**；开发态则 `spawn` 用 `tsx` 跑 `server/src`。可设 `SPAWN_SERVER=false` 改用外部独立服务。
- 启动后调用 `waitForServer()` 轮询 `GET /api/health` 直到就绪（超时 45s）。
- 前端由内置后端**同源托管**（`mainWindow.loadURL(SERVER_ORIGIN)`），避免 `file://` 下的 CSP/CORS 限制：

```249:249:electron/main.ts
void mainWindow.loadURL(IS_DEV ? DEV_URL : SERVER_ORIGIN);
```

- 若后端起不来，弹窗区分「测试库 / 线上库」给出排查提示（本地 MongoDB 是否启动、云库 `MONGODB_URI_PROD` 与 IP 白名单是否正确）。

## 5. 后端与数据库：测试库 vs 线上库

文件：`server/src/config.ts`、`server/src/env.ts`、`server/src/db.ts`

### 5.1 数据环境判定
- `COMIC_DATA_ENV=prod`（或 `NODE_ENV=production`）→ **线上云库**。
- 否则 → **测试库**（开发/未打包）。
- 环境变量加载顺序：线上优先 `.env.prod`，开发优先 `.env`，互不覆盖（见 `server/src/env.ts`）。

### 5.2 MongoDB 连接串
```17:34:server/src/config.ts
const DEFAULT_TEST_URI = 'mongodb://127.0.0.1:27017/zhenjian-comic';
function resolveMongoUri(env: DataEnv): string {
  if (env === 'prod') {
    const uri = String(process.env.MONGODB_URI_PROD || '').trim();
    if (!uri) throw new Error('缺少线上数据库连接串 MONGODB_URI_PROD ...');
    return uri;          // 线上：只认 MONGODB_URI_PROD，缺失直接报错，绝不回落本地库
  }
  return process.env.MONGODB_URI || DEFAULT_TEST_URI;
}
```

### 5.3 连接行为（`server/src/db.ts`）
- `mongoose.connect(config.mongoUri, { serverSelectionTimeoutMS: 15000, maxPoolSize: 10 })`。
  - `maxPoolSize: 10`：针对 Atlas 免费版(M0)连接数上限做的收紧。
- **线上环境连接失败直接抛错**（绝不回落内存库，否则重启丢数据且问题被掩盖）。
- **非线上环境**连接失败时，自动启动 `mongodb-memory-server` 内存库兜底（进程退出数据不保留，仅用于本地没有 MongoDB 时也能跑起来）。

> 因此所谓「连接线上数据」，就是让正式包以 `prod` 环境运行，并把 `MONGODB_URI_PROD` 指向**腾讯云 MongoDB（Atlas 或自建）**。数据库里存的是漫画元数据、章节、用户、书架、评论、反馈、举报等所有业务数据。

## 6. 外部漫画源：抓取 + 图片代理

文件：`server/src/routes/media.ts`、项目 `crawler/`

### 6.1 远程图片代理（为什么页图不直接用原 URL）
外部图片站（MangaDex / dm5 / 包子漫画）带**防盗链**，浏览器 `<img>` 无法跨域伪造 `Referer`，会 404。
所以阅读器页图统一由后端 `/media/img` 代理取回、再同源返回前端：

```35:56:server/src/routes/media.ts
const ALLOWED_IMG_HOSTS = ['.mangadex.network', 'uploads.mangadex.org', '.cdndm5.com', '.6wm.top'];
// ...
router.get('/img', async (req, res) => {
  const raw = String(req.query.u || '');
  // ... 校验白名单、按主机推导 Referer（SSRF 防护 + 防盗链）
```

- 仅允许白名单主机，防止 `/media/img` 被当成开放代理（SSRF）。
- 按目标主机推导正确的 `Referer`（如 `baozimh.org`、`dm5.com/m<cid>/`、`mangadex.org`）。
- 封面/缺图占位则直接用服务端生成的 SVG（`/media/cover.svg`、`/media/page.svg`），不依赖外网。

### 6.2 漫画内容来源
漫画本体由 `crawler/` 下的爬虫（对接 MangaDex、动漫屋 dm5、包子漫画 baozimh 等公开源）抓取，
经后端 `POST /api/comics/fetch`（管理员「漫画导入」触发）入库到 MongoDB。

## 7. 应用更新（版本检查）链路

文件：`web/src/api.ts`（`appLatest`）、`server/src/routes/app.ts`、`web/src/version.ts`

- 前端「检查更新」调用 `GET /api/app/latest`。
- 后端优先读取**远程 manifest**（`config.updateManifestUrl`，即上传到 COS 的 `version.json`），
  失败则回退到环境变量 `APP_LATEST_VERSION` / `APP_UPDATE_URL` / `APP_UPDATE_NOTES`：

```63:84:server/src/routes/app.ts
if (config.updateManifestUrl) {
  const r = await fetch(config.updateManifestUrl, { headers: { Accept: 'application/json' } });
  // ... 容错解析（去掉尾随逗号），取最新版本 + 全量版本列表
}
res.json(latest);
```

- 本地当前版本号来自 `package.json.version`，经 Vite 注入 `__APP_VERSION__`，运行时再用 Electron 桥 `appVersion` 覆盖（`web/src/version.ts`）。`isNewer()` 做语义化比较。

> 实操上：`version.json` 会生成并上传到 COS（`https://vaultix-1302257136.cos.ap-chengdu.myqcloud.com/comic/version.json`），
> 后端通过 `APP_UPDATE_MANIFEST_URL` 指向它即可让所有客户端检测更新——这就是「线上更新数据」的另一条通道。

## 8. 关键环境变量速查

| 变量 | 作用 | 默认值 / 来源 |
|---|---|---|
| `COMIC_DATA_ENV` | `prod` 切线上库；否则测试库 | 打包时自动 = `prod` |
| `MONGODB_URI_PROD` | **线上 MongoDB 连接串（必填）** | 无则线上启动报错 |
| `MONGODB_URI` | 测试库连接串 | `mongodb://127.0.0.1:27017/zhenjian-comic` |
| `COMIC_SERVER_ORIGIN` | 前端使用的后端地址 | `http://127.0.0.1:9527`（main.ts 注入） |
| `PORT` | 后端监听端口 | `9527` |
| `SPAWN_SERVER` | `false` 时跳过内置后端、用外部服务 | 默认启动内置 |
| `JWT_SECRET` | 登录 token 签名密钥 | 开发默认弱密钥 |
| `APP_UPDATE_MANIFEST_URL` | 远程 version.json 地址（更新检测） | 空 → 用下方静态值 |
| `APP_LATEST_VERSION` / `APP_UPDATE_URL` / `APP_UPDATE_NOTES` | 静态更新信息兜底 | 空 |

## 9. 典型时序

**看漫画（含图片）**
1. 前端 `api.chapter(id)` → `GET /api/comics/chapter/<id>`。
2. 后端从 MongoDB 取章节元数据与页图**原始 URL**。
3. 前端拿到页图 URL，经 `pageImageUrl()` 改为 `/media/img?u=<远程URL>`。
4. 后端 `/media/img` 代取远程 CDN（带正确 Referer、过白名单），同源返回给 `<img>`。

**登录**
1. `api.login()` → `POST /api/auth/login`，后端校验后返回 `token`。
2. 前端 `setToken()` 存入 `localStorage`，后续请求自动带 `Authorization: Bearer`。

**检查更新**
1. `api.appLatest()` → `GET /api/app/latest`。
2. 后端拉取 COS 上的 `version.json`（或静态环境变量）返回最新版本。
3. 前端用 `isNewer()` 与本地 `APP_VERSION` 比较，有更新则提示。

---

## 10. 小结

- **数据连接的「开关」就是 `COMIC_DATA_ENV` / `MONGODB_URI_PROD`**：正式包默认连线上云库；本地开发连本机 27017。
- 前端永远打 `http://127.0.0.1:9527`（由 Electron 注入），后端地址对前端透明。
- 漫画内容与图片来自外部源，经**爬虫入库 + 图片代理**统一收口，前端只认同源后端。
- 应用更新信息走 **COS 上的 `version.json`**（经后端 `/api/app/latest` 暴露）或环境变量。
